# Decisions

Status: M4 release-candidate implementation; npm publication pending.

1. **Provider truth over inferred quotas.** Use provider reset times and actual limits. Why: token counts cannot establish subscription percentages. Cost: unknown status where evidence is insufficient.
2. **Separate source freshness from probe time.** Add sourceObservedAt for local samples. Why: rereading historical logs must not produce fresh green status. Cost: small contract extension.
3. **Documented Codex live protocol; local logs as fallback.** Why: logs are historical and may be locked. Cost: subprocess/protocol compatibility work and explicit unknown during failures. No undocumented credential scraping endpoints.
4. **Scope OpenRouter meters explicitly.** Ordinary key budgets and management-key account credits differ. Why: avoid misleading availability claims and unnecessary privileged credentials. Cost: extra scope metadata and incomplete status until authenticated verification.
5. **Privacy means no telemetry, not no networking.** Only configured provider reads and opt-in alert delivery may leave the machine. Credentials remain locally stored but must be transmitted to their intended authentication endpoint over HTTPS. Why: quota reads and notifications cannot work without contacting the destination explicitly selected by the user. Cost: external channels necessarily receive alert content. Desktop-only alerts remain possible.
6. **Zero required infrastructure spend.** No paid inference is needed for monitoring. Why: meet the cost goal realistically. Cost: third-party free-tier availability cannot be guaranteed forever; provider subscriptions themselves are outside watchdog costs.
7. **SQLite behind one interface.** Why: isolate storage and enable a future Postgres implementation. Cost: one abstraction now; hosted reuse is not a promise of zero future migration work. Node 20 needs a compatible SQLite dependency rather than unconditional node:sqlite.
8. **Next.js local dashboard as requested.** Why: reuse for a possible later hosted version. Cost: heavier install/startup; package standalone assets explicitly and disable framework telemetry. Bind IPv4 loopback and protect state-changing test-alert requests against cross-origin triggers.
9. **Pacing must account for coverage and resets.** Keep specified 100/daysUntilReset as a labeled full-quota reference; use remainingPct/daysUntilReset for a safe remaining-budget recommendation. Why: full-quota allowance can overspend a partly used window. Cost: additional explanation. Never difference percentages across resets, bucket changes or top-ups; insufficient coverage means unknown ETA.
10. **Durable alerts need delivery state.** Unique event identity alone can lose notifications after a crash. Persist pending/delivered attempts and retry. Why: a restart between threshold detection and delivery must not silently discard the alert. Cost: outbox state. Exactly-once external delivery cannot be guaranteed for channels without idempotency support. Non-resetting credit needs a defined period identity before implementation.
11. **Milestone gate preserved.** Why: the supplied build brief explicitly requests waiting for continue after each stage, so each stage remains reviewable before scope expands. Cost: delivery pauses at every gate even when the next stage is technically unblocked.

12. **M1 live probe verified; suspect timing fails closed.** The installed Codex App Server accepts initialization and quota reads. Its real response reports a 300-minute window with reset more than 300 minutes in the future at capture. Why: treating inconsistent timing as healthy violates the unknown-state promise. Cost: UNKNOWN until semantics are verified or provider data changes. Capture is sanitized to quota fields only.
13. **Modern development tools, older runtime support.** Upgrade vulnerable test dependencies instead of preserving old Vitest solely for Node 20 development. Why: dependency audit found critical development-tool advisories. Cost: development requires Node 22.13+; distributed CLI still targets Node 20 and has only YAML and Zod runtime dependencies.
14. **Conservative M1 data coverage.** File mode is explicitly selected, bounded to 8 MiB, and rejects incomplete JSONL. Pacing refuses incomplete horizons, reset crossings and counter decreases; no persistence yet. Why: avoid invented rates. Cost: more unknown results, including weekly averages spanning unmeasured resets; interval-aware history aggregation is M2 work.
15. **One real webhook path.** M1 sends once to the first configured generic webhook, verifies HTTP success and does not follow redirects. Why: demonstrable end-to-end delivery without external secrets. Cost: retry/fallback and other channel types remain M2 work; local receiver validation does not prove external destination delivery.

16. **Native SQLite pinned to better-sqlite3 11.10.0.** Why: this release declares Node 20 support while the current major requires Node 22. Cost: native install artifacts vary by OS/Node; the packed release therefore installs SQLite for the target machine and CI cold-installs it under Node 20. npm workspace development uses Node 22.13+ because Vitest 5 requires it.
17. **Atomic sample and alert creation, leased outbox.** A transaction records each metric and inserts threshold crossings with a unique `provider|bucket:window|threshold|periodEpoch` key. Due alerts are leased before delivery and retried with exponential backoff. Why: concurrent polls and process restarts should not emit duplicate crossings or lose pending events. Cost: SQLite is the local coordinator; third-party channels without idempotency cannot guarantee exactly-once delivery after a crash between send and acknowledgement.
18. **Credit periods start on top-up or refill.** If a non-resetting credit limit changes or used percentage decreases, start a new monotonically increasing epoch. Why: renewed balances can legitimately cross thresholds again. Cost: a provider correction may also be interpreted as a new credit period; true source semantics remain UNVERIFIED for OpenRouter.
19. **Pacing requires 80% coverage.** Infer burn from valid adjacent observations within two poll intervals, skipping reset discontinuities, and show both seven-day and six-hour horizons. Why: sparse data must not produce precise-looking ETAs. Cost: initial and frequently disconnected installations show unknown pace. Current UTC daily burn is compared with remaining quota divided by days until reset; the full-quota `100/days` figure stays a reference, not the spending recommendation.
20. **Five free channels with ordered fallback.** Generic webhook, ntfy, Telegram and Discord use HTTPS; desktop uses native OS notification commands. Why: no paid infrastructure. Cost: desktop delivery requires a graphical session and has no remote integration test; provider-specific success shape is checked for Telegram, while HTTP success is used for the other channels.
21. **Read the same SQLite from Next.js route handlers and server pages.** Why: avoid a second API process or duplicated quota logic. Cost: the npm artifact carries a heavier Next.js runtime. Webpack externalizes SQLite so the target machine's normal CLI dependency supplies the native module; the artifact itself contains no build-machine `.node` binary.
22. **Bind loopback and reject foreign Host/Origin.** Why: browser requests to a local server still need DNS-rebinding and CSRF defenses. Cost: only the literal `127.0.0.1` hostname works, which is acceptable for v1. Read errors, stale health and stale samples render UNKNOWN.
23. **Motion is decoration.** Lenis and GSAP load client-side only when reduced motion is not requested; quota state stays legible without them. Why: animations must not obscure warnings or add work for users who opt out. Cost: two additional frontend dependencies for restrained motion requested by the user.
24. **Use React Bits as part of the application, with attribution.** A second review of the current MIT + Commons Clause text confirmed that components may be used and distributed as part of an application or product; the restriction is on selling, sublicensing or redistributing the components themselves. CliffWatch includes an adapted SpotlightCard, its copyright/license notice and a source link. Why: the requested interaction can be included while preserving the upstream license and attribution. Cost: the component is application source and must not be repackaged as a standalone UI library.
25. **Resolve relative database paths beside config.** Why: the CLI and standalone dashboard have different working directories, so a raw relative path could silently split history across two SQLite files. Cost: relative `dataFile` semantics now follow the config location instead of the shell's working directory.
26. **Use the target machine's SQLite native module.** The dashboard standalone bundle excludes the builder's `better-sqlite3` and Sharp native packages; `better-sqlite3` remains a normal CLI dependency installed for the user's OS and Node version. Why: a Windows-built tarball must not silently carry a Windows-only SQLite binary. Cost: installation may compile SQLite locally when a matching prebuilt binary is unavailable; cross-platform CI and clean package checks are necessary.
27. **Test a packed release on two OSes.** CI builds on Windows and Linux with Node 22, then installs the npm tarball and exercises CLI, dashboard and SQLite with Node 20. Why: source tests cannot catch missing standalone assets or native module resolution. Cost: CI takes longer and consumes free runner minutes.
28. **Stage publication separately.** The package is versioned and packable, but publishing requires an authenticated npm account and an explicit final approval. Why: npm publication is externally visible and cannot be treated like a local reversible build. Cost: `npx cliffwatch status` remains a release target, not a current public command, until publication is completed.
29. **Rename the product to CliffWatch while preserving the repository folder.** The CLI, package, local data directory, environment variables, dashboard and documentation use the new identity. Why: the user selected a stronger product name and supplied its visual identity. Cost: pre-release QuotaDog configs are not migrated automatically because no public release exists yet.
30. **Make optional providers opt-in.** Codex starts enabled; OpenRouter starts disabled until the user explicitly enables it and supplies a key. Why: the first-run dashboard should show the provider the user already authenticated, rather than a global UNKNOWN caused by an unrelated missing credential. Cost: OpenRouter users perform one extra configuration step.
31. **Rediscover Codex for every poll batch.** Resolve a configured command from PATH, then scan known install roots, and treat an absolute configured path as an explicit fallback. Why: desktop updates replace version-hashed executable directories. Cost: each poll performs a small amount of local filesystem work and platform install layouts remain a maintained compatibility surface.
32. **Show snapshot age instead of implying live synchronization.** Dashboard refreshes only re-read SQLite; stale values remain visible with age and stale treatment, while `sync-now` deliberately performs a provider poll. Why: CLI live probes and persisted dashboard samples represent different observations. Cost: users who need a current dashboard value perform an explicit sync and the UI carries more timestamp detail.
33. **Add tools through a loopback-only test-before-save flow.** The dashboard detects supported local tools, performs a real probe, shows the first trusted reading, and only then enables saving. OpenRouter secrets travel only in the local POST body and are persisted through Windows user environment input over subprocess stdin; YAML stores the environment variable name. Why: ordinary users should not edit YAML while the product still preserves local-first credential handling and UNKNOWN discipline. Cost: automatic secret persistence is Windows-only for now; POSIX users must configure the environment themselves, and unsupported Claude remains visibly disabled.
34. **Predictive alerts are evidence-gated and opt-in.** A warning requires at least 80% valid observation coverage, an exhaustion ETA inside the configured lead time, and exhaustion before reset. Why: projections with sparse history are more harmful than no warning. Cost: new installations do not predict until enough history exists, and upgrades do not silently enable a new notification policy.
35. **Migrate SQLite in place and retain bounded history.** `PRAGMA user_version` advances additive schema migrations; integrity diagnostics and indexed range reads stay behind the Store interface. The daemon prunes old samples in bounded batches. Why: long-running local installs need predictable disk and upgrade behavior. Cost: the local schema and migration tests become a maintained compatibility surface.
36. **Use a limited user service on Windows.** Optional lifecycle commands manage an `ONLOGON` Task Scheduler entry at `LIMITED` privilege. Why: monitoring should survive restarts without requiring an Administrator service. Cost: other operating systems continue to use their native service manager.
37. **Alert actions preserve audit history.** Snooze moves the next delivery time; acknowledge removes a pending alert from delivery without deleting its row. Why: users need control without losing evidence. Cost: one additive SQLite column and a same-origin dashboard mutation route.
